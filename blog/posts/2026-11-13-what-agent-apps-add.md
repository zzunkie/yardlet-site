I make [Yardlet](https://github.com/zzunkie/yardlet), a free, open-source Mac app that runs coding agents like Claude Code and Codex in one window. So I make one of the apps in this post, and you should read it with that in mind. I've linked every claim to the app's own code at a fixed commit or to its documentation, as of November 13, 2026. Where I couldn't find out, I say so.

An app that runs several agents at once has to know what each one is doing: working, waiting for you, or done. Claude Code and Codex were built to be used directly, so each desktop app picks its own way to find out. That choice decides what the app adds to the agent and what stays on your Mac after you stop using it.

Apart from Yardlet, each app here is a commercial product or part of an open-source project with at least 10,000 stars on GitHub.

## How an app finds out what the agent is doing

**Hooks in the agent's own settings.** Claude Code and Codex both run commands you register at points in a session: when a turn ends, when the agent needs permission, when it sends a notification. Both document this as an extension point. Claude Code reads hooks from `~/.claude/settings.json` for every project, from a project's `.claude/settings.json` and a few other places ([docs](https://code.claude.com/docs/en/hooks)); Codex reads them from `~/.codex/hooks.json` or a `[hooks]` table in `~/.codex/config.toml`, and asks you to review and trust a hook before it runs ([docs](https://learn.chatgpt.com/docs/hooks)). A hook registered there tells the app exactly when a turn ends or a permission prompt appears, even when the agent runs as its normal terminal UI, and it works for any agent that has hooks. The catch is where it lives. A hook in your global settings runs in every session of that agent, including the ones you start in Terminal with the app closed, and it stays after you drag the app to the Trash unless something removes it. Orca and Paradev (Superset until October) work this way, and both make their hooks exit at once outside their own terminals.

**Hooks for one process.** A terminal app can put its own `claude` and `codex` in front of the real ones in the shells it opens, as a shell function or a script early on `PATH`. The wrapper then hands the agent hooks for that process only: Claude Code takes extra settings with `--settings <file>` ([CLI reference](https://code.claude.com/docs/en/cli-reference)), and Codex takes config overrides with `-c`. cmux does this, and leaves your settings files alone. The cost is that the command you type isn't quite the command that runs. In May a cmux release added `--allow-dangerously-skip-permissions` to every `claude` launch so a button could switch to bypass mode later. The flag doesn't turn bypass on by itself (Yardlet passes it too; see note 25 below), but in the terminal UI it sent ordinary `claude` starts down Claude Code's dangerous-mode path, as [the fix](https://github.com/manaflow-ai/cmux/pull/3564) describes. A user [reported it](https://github.com/manaflow-ai/cmux/issues/3547) about an hour after the release, and the maintainer removed it the same day.

**A signal from the terminal.** Claude Code 2.1.295 [added](https://github.com/anthropics/claude-code/blob/6e1e44f6433bfa17d198e932bff53373aa229eea/CHANGELOG.md#L1547-L1550) the Program Status Protocol, an escape sequence (OSC 7501) that tells a terminal whether it's working, waiting on you, or done, and Codex [reports it too](https://github.com/openai/codex/pull/52725) since a change merged in October. A terminal app that reads it needs nothing installed anywhere. The Herdr app relies on it alone; cmux and Orca read it alongside their hooks ([cmux](https://github.com/manaflow-ai/cmux/blob/12023d89feb5425c766ba05e8d8e4cfc176e3991/Sources/Workspace+ProgramStatus.swift#L8-L25), [Orca](https://github.com/stablyai/orca/blob/b0570d90fc9af8c9e7e3566c0fb841d0884e2462/src/main/agent-hooks/README.md#L1-L14)). It only works with recent versions of the agents, and it says less than a hook: Claude Code sends the state and one short line, such as what it wants approved, and Codex so far sends the state alone ([Orca's notes](https://github.com/stablyai/orca/blob/b0570d90fc9af8c9e7e3566c0fb841d0884e2462/src/main/agent-hooks/README.md#L40-L50)).

**The agent's own protocol.** Claude Code can run as a process that reads and writes JSON events (`-p --input-format stream-json --output-format stream-json`), which is also how the Claude Agent SDK drives it. Codex has an [App Server](https://learn.chatgpt.com/docs/app-server) that speaks JSON-RPC, the interface its VS Code extension uses. Many other agents speak the [Agent Client Protocol](https://agentclientprotocol.com). An app that drives the agent this way gets turns, tool calls and approval requests as data, so it needs no hook and no wrapper. T3 Code, Paseo, Vibe Kanban and Yardlet work this way, and Orca and Paradev use it for their chat views. The cost is on the app's side: it draws the conversation itself instead of showing the agent's own terminal UI, it supports only agents that have such a protocol, and it waits on whatever the protocol doesn't expose yet.

## What else comes along

Knowing the agent's state is only part of it. Some apps also add their own text to the system prompt, so the agent knows it's inside the app: how to link a pull request, how to hand work to another agent. It works, and it means the agent you talk to isn't quite the one in its own app. Some install skills into the agent's global skills folder. Some mark their folders as trusted in the agent's config. Which permission mode a new session starts in also differs from app to app, but that is a preference, and many people run with checks off on purpose, so I've left it out.

## Yardlet, the same way

Yardlet runs Claude Code with `--print --input-format stream-json --output-format stream-json` and Codex as `app-server --stdio`; OpenCode, Antigravity, Kimi Code, Grok Build and Hermes go over ACP ([Claude](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Adapters/Claude/ClaudeProcessTransport.swift#L165-L177), [Codex](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Adapters/Codex/CodexProcessTransport.swift#L86)). It registers no hooks and writes nothing into `~/.claude`, `~/.claude.json` or `~/.codex`. Its terminal panel starts your login shell with four variables (`TERM`, `COLORTERM`, and `cat` as `PAGER` and `GIT_PAGER`) and nothing in front of the agent commands ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Runtime/ShellLaunchEnvironment.swift#L20-L28)).

Here is what Yardlet adds:

- **Its MCP server.** Each Codex, Claude Code and ACP session Yardlet starts gets `yardlet-mcp` through that session's own option, which I wrote about in [an earlier post](/blog/mcp-server-without-settings.html). The agent then sees the server's instructions, about 900 characters on how to use the browser and task tools ([text](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/YardletAgentTools/AgentToolCatalog.swift#L84-L100)), and the descriptions of up to 46 tools of its own, 21 of them for the browser ([list](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/AgentToolBroker.swift#L319-L334)), plus the tools of any connectors you've signed in to.
- **Turning the tools off.** Settings › General › Agent browser tools takes the browser tools (20, or 21 with a saved password) out of sessions started afterwards ([setting](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Domain/YardletSettings.swift#L316-L319)), Share the terminal with agents removes one more, and a connector can be turned off for a task. The other 24 tools and the instruction text stay: there is no switch yet that starts a session without the server ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/AgentToolBroker.swift#L151-L152)).
- **Claude Code's launch options.** Its own task, session and settings tools are pre-approved with `--allowedTools`, so Claude Code doesn't ask before them ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/AgentToolInjection.swift#L35-L39)). The claude.ai account's own connectors are off unless you turn them on in Settings, because Yardlet's connectors are shared by every account ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/AgentToolInjection.swift#L172-L178)). And when a Yardlet connector serves the same address as one of your own MCP servers, that server is left out of the process with `--settings` ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/AgentToolInjection.swift#L58-L62)).
- **Permission modes.** Yardlet sets the mode on each Codex thread, Ask for approval unless you pick another, so a default in your `config.toml` applies only if you pick Custom ([thread](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Adapters/Codex/CodexProtocol.swift#L74-L89), [values](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Domain/CodexCapabilities.swift#L108-L150)). To Claude Code it passes `--allow-dangerously-skip-permissions`, so you can switch a session to Bypass later; sessions start in Claude Code's default mode ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Adapters/Claude/ClaudeProcessTransport.swift#L165-L177)).
- **Yardlet instructions.** Text you write in Settings goes to the agents that take extra instructions for one session (Claude Code, Codex, Grok Build, Pi and Antigravity), appended to Claude Code's system prompt and as Codex's developer instructions. It's empty unless you write something, and Yardlet adds no words of its own to it ([source](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/AgentTools/YardletInstructions.swift#L181-L184)). One exception: an optional daily routing evaluation, off by default, adds a short note on which agent and model to use for which kind of work when you turn it on ([default](https://github.com/zzunkie/yardlet/blob/e4c1fbee798bba778bbdcf86fa27fc106993348b/Sources/NativeHarnessClient/Domain/RoutingEvaluation.swift#L120)).

The protocol route has its costs here too. Cursor Agent, Pi and Muse Code have no way to take an MCP server for one session, so their tasks in Yardlet run without its tools. Yardlet shows a conversation it draws itself, not Claude Code's or Codex's terminal UI.

## Memory at rest

The last column of the table comes from [the post I published on November 11](/blog/agent-apps-memory-cpu.html), measured on November 9 and 10 on one MacBook Pro (M1 Pro, 16 GB, macOS 15.6.1). Each app was opened for the first time in an empty home folder, left alone for a minute and sampled for two; memory is the `phys_footprint` sum of every process macOS charges to the app, the number Activity Monitor shows. The agent CLIs were stand-ins and aren't counted, which leaves out the Codex App Server Yardlet starts at launch. Conductor and Superset (now Paradev) were measured at their sign-in screens, and cmux was playing its welcome video; on a second launch it used 168 MiB. Vibe Kanban wasn't in that run.

With ten tasks streaming at once, Yardlet used 214 MiB, T3 Code 867 MiB and Paseo 987 MiB; the others weren't run under load. That post has the per-run data, where Yardlet does worse, and what the numbers leave out.

## Checking your own Mac

If you've tried a few of these apps, this shows what they left behind:

```sh
# Hooks every session runs
grep -n '"command"' ~/.claude/settings.json
cat ~/.codex/hooks.json
grep -n -A3 '^\[hooks' ~/.codex/config.toml

# Skills every session loads
ls ~/.claude/skills ~/.agents/skills

# Run in an app's terminal
type claude codex

# A running agent's flags
ps -o args= -p "$(pgrep -nx claude)"
```

An app's own hook usually checks a variable that only its terminals set, so finding one doesn't mean it does anything in your other sessions. If you want it gone, the app's own switch is the safer way to remove it, where there is one.
